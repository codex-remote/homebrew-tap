# Codex Remote 0.2.0-beta.2

This Beta supersedes `0.2.0-beta.1`, which cannot start Valkey from the default
macOS `Application Support` state path.

> [!WARNING]
> This proprietary Beta is not signed with Apple Developer ID and is not
> notarized by Apple. It is intended for testing and carries no production
> support commitment. Do not disable Gatekeeper globally.

## Fixed

- Quote and escape the Valkey data directory and password before writing its
  configuration, including paths with spaces, quotes, and backslashes.
- Reject CR, LF, and NUL in generated Valkey configuration values.
- If startup fails, unload only the LaunchAgents started by the current attempt
  and preserve pre-existing services and user data.

## Install

```bash
brew install codex-remote/tap/codex-remote
codex-remote setup --workspace-root ~/work
codex-remote pair
```

## Upgrade from beta.1

```bash
brew update
brew upgrade codex-remote
codex-remote setup --repair
```

Run Setup or repair from an external Terminal. Preserve
`~/Library/Application Support/CodexRemote`; the repair path reuses the existing
PostgreSQL data and Keychain credentials.

## Known limitations

- Unsigned and not Apple notarized.
- Local-network access only; no public TLS endpoint.
- Concurrent refreshes from multiple Safari tabs can trigger replay protection
  and revoke the session.
- Only Apple Silicon is supported.
